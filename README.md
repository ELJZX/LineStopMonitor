# Line Stop Monitor

Система контроля остановок производственной линии на базе контроллера
**Delta DVP12SE11R** (Ethernet) и Android-планшета.

Планшет читает по **Modbus TCP** состояние линии с ПЛК, фиксирует моменты
остановки/запуска, показывает статус «ОК» / «АВАРИЯ» и заставляет оператора
закрыть каждый случай остановки выбором причины.

## Как взаимодействуют компоненты

```
 ┌───────────────┐  24 В (уровень)   ┌─────────────────────────┐
 │ Линия         │ ───────────────►  │  DVP12SE11R (ПЛК)       │
 └───────────────┘  X0 = авария      │  X0 — вход сигнала      │
                    (есть, пока      │  M10/M11 — защёлки      │
                     линия в аварии) │  D0..D7, D100..D103     │
                                     └───────────┬─────────────┘
                                                 │ Modbus TCP :502
                                                 │ (Ethernet, IP 172.16.29.150)
                                                 ▼
                                     ┌─────────────────────────┐
                                     │  Android-планшет        │
                                     │  ModbusTcpClient        │
                                     │  LineStopViewModel      │
                                     │  AlarmStore (JSON)      │
                                     │  Compose UI             │
                                     └─────────────────────────┘
```

Сигнал аварии — **уровневый**: 24 В присутствуют всё время, пока линия в аварии,
и пропадают в момент запуска линии.

**ПЛК** — «железная» часть: следит за уровнем `X0`, ловит фронт/спад, ведёт
счётчики и измеряет длительность аварии (`D6`/`D7`, 0.1 с). Работает автономно.

**Android** — «человеческая» часть: опрашивает ПЛК каждые 200 мс, по фронту/спаду
`D0` понимает начало и конец аварии, хранит историю и ведёт диалог с оператором.

### Сценарий работы

| Шаг | Что происходит | ПЛК | Android |
|-----|----------------|-----|---------|
| 1 | На **X0** появились постоянные 24 В (линия встала) | `D0 = 1` | видит фронт `D0`, создаёт активную «АВАРИЮ», пишет время начала |
| 2 | 24 В пропали (линию запустили) | `D0 = 0`, `INC D1` | видит спад `D0`, фиксирует конец и **длительность**, **показывает диалог выбора причины** |
| 3 | Оператор выбрал причину | — | пишет `D100 = код`, затем `D101 = 1` |
| 4 | Квитирование | `D5=D100`, `INC D4`, `D101=0`, `D100=0` | видит `D4+1`, закрывает случай, статус «ОК» |

Если диалог закрыли кнопкой «Позже» — случай остаётся активным, на главном
экране горит «АВАРИЯ» и есть кнопка «Указать причину». Так каждый случай
обязательно закрывается причиной.

Если датчик сработал, **а смена ещё не начата**, приложение само предлагает
принять смену («Требуется начать смену»): после ввода оператора и механика
авария фиксируется, начиная с момента срабатывания датчика.

### Главный экран

* **Статус**: `ЛИНИЯ В РАБОТЕ` (зелёный, большая галочка справа) /
  `АВАРИЯ` (пульсирующий красный фон, большой восклицательный знак справа) /
  `НЕТ СВЯЗИ` (серый). Незакрытые случаи остаются видимыми списком.
* **Смена оператора** — кнопка «Начать работу» (ввод фамилии **оператора** и
  **ответственного механика**) превращается в «Закончить работу»
  (подтверждение «Да/Нет»).
* **Активные аварии** — начало, конец, длительность, кнопка «Указать причину».
* **История** — все закрытые случаи с причиной и периодом аварии.
* **Журнал** — подробный журнал событий из базы данных.
* **Настройки** — IP и порт контроллера, очистка истории и журнала.

### Хранение данных (SQLite)

База `linestop.db` (см. `data/AppDatabase.kt`):

| Таблица | Содержимое |
|---------|------------|
| `alarms` | каждый случай аварии: время начала/конца, длительность, причина, смена |
| `shifts` | смены: оператор, ответственный механик, начало, конец |
| `logs`   | подробный журнал: время, уровень, категория, сообщение, ссылки на аварию/смену |

Логируются: запуск/закрытие приложения, подключение и обрыв связи с ПЛК,
начало и конец аварии, выбор причины, отправка и подтверждение квитирования,
начало и конец смены, очистка истории.

## Карта регистров (кратко)

Полностью — в [`plc/REGISTER_MAP.md`](plc/REGISTER_MAP.md).
Modbus-адрес регистра `Dn` = `0x1000 + n`.

| Регистр | Напр. | Смысл |
|---------|-------|-------|
| D0 | R | 0 = линия работает, 1 = авария (уровень X0) |
| D1 | R | счётчик запусков (по спаду X0) |
| D4 | R | счётчик квитирований |
| D5 | R | код последней причины |
| D100 | W | код причины от Android |
| D101 | W | запрос квитирования (Android пишет 1, ПЛК сбрасывает) |

## Сборка и установка

### Android Studio

1. `File → Open` → папка `CheckStopFinnah`.
2. Синхронизировать Gradle (AGP 9.2.1, Gradle 9.4.1, JDK 17+).
3. `Run ▶` на подключённом планшете.

### Командная строка (Windows, JDK из Android Studio)

```powershell
$env:JAVA_HOME="C:\Program Files\Android\Android Studio\jbr"
.\gradlew.bat assembleDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk`

Установка на планшет:

```powershell
adb install -r app\build\outputs\apk\debug\app-debug.apk
```

> Проверено: проект собирается, APK формируется (~11.7 МБ).

### Первый запуск

1. Планшет и ПЛК — в одной подсети (`172.16.29.x`).
2. В приложении «Настройки» → IP `172.16.29.150` → Сохранить.
3. Статус сменится на «ОК»; в шапке появится «Связь: 172.16.29.150».

## Android-эмулятор (AVD)

На этом ПК уже создан AVD **`LineStop`** (Pixel Tablet, API 35, x86_64,
ландшафт, WHPX-ускорение) и установлено `cmdline-tools`.

```powershell
$sdk = "$env:LOCALAPPDATA\Android\Sdk"
& "$sdk\emulator\emulator.exe" -avd LineStop
# в другом окне, когда эмулятор загрузится:
& "$sdk\platform-tools\adb.exe" install -r app\build\outputs\apk\debug\app-debug.apk
```

Проверка связки «приложение ↔ эмулятор ПЛК на ПК»:

```powershell
py -3 simulator\plc_sim.py --port 502     # отдельное окно (можно --port 1502)
& "$sdk\platform-tools\adb.exe" reverse tcp:502 tcp:502
# в приложении: Настройки -> IP 127.0.0.1, порт 502
```

Сигнал аварии без консоли: запись `D200=1` (поднять аварию) / `D200=2`
(снять = запуск линии) через любой Modbus-клиент (см. `simulator/README.md`).

## Веб-мониторинг

Отдельный сервер принимает все события приложения и складывает их в SQLite3,
показывая живую панель. Работает на стандартной библиотеке Python (без Flask).

```powershell
py -3 web\server.py --host 0.0.0.0 --port 8080 --db web\linestop_web.db
# панель: http://localhost:8080/
```

Возможности панели: **фильтр аварий по датам, операторам и механикам**,
**агрегаты** (по причинам и по дням, суммарная/средняя/максимальная
длительность) и **экспорт в Excel** (`.xlsx` с листами «Аварии», «По причинам»,
«По дням», «Сводка»). Экспорт учитывает выбранный фильтр.

Отдельная вкладка **«Смены»** — журнал по сменам: начало и конец смены,
автопредложение принять смену (сработал датчик без смены) и отклонение этого
предложения; с фильтром по датам/оператору/механику и экспортом в Excel.

В приложении: **Настройки → «Адрес сервера мониторинга»** — например
`http://172.16.29.1:8080` (пусто — отправка выключена). События уходят пачками
на `POST /api/events`, при обрыве связи остаются в очереди и досылаются позже.

API: `GET /api/events`, `GET /api/alarms?from=&to=&operator=&mechanic=`,
`GET /api/summary?...`, `GET /api/filters`, `GET /api/shift-events?...`,
`GET /api/export.xlsx?...`, `GET /api/export-shifts.xlsx?...`,
`GET /api/stats`, `GET /api/health`.

Для эмулятора Android адрес хоста — `10.0.2.2`, либо проброс портов:

```powershell
& "$sdk\platform-tools\adb.exe" reverse tcp:8080 tcp:8080
# в приложении: http://127.0.0.1:8080
```

Сквозной тест «ПЛК → приложение → веб» (эмулятор ПЛК + логика + сервер):

```powershell
py -3 -m unittest discover -s simulator -p "test_*.py" -v   # 11 тестов
py -3 -m unittest web.test_server -v                        # 27 тестов
```
