# Протокол ПЛК ↔ приложение

## Параметры соединения

| Параметр | Значение |
|----------|----------|
| Контроллер | Delta DVP12SE11R (Ethernet) |
| Транспорт | Modbus TCP, роль slave |
| Порт | `502` (по умолчанию, настраивается в приложении) |
| Unit ID | `1` |
| IP по умолчанию | `172.16.29.150` (настраивается) |
| Преобразование адреса | Modbus-адрес `Dn` = `0x1000 + n` |
| Функции | FC `0x03` чтение, FC `0x06` запись одного, FC `0x10` запись нескольких |

Порт и IP хранятся в `SharedPreferences` (`plc_ip`, `plc_port`) и меняются в
экране «Настройки» (см. [`UI.md`](UI.md)).

## Карта регистров

Адреса соответствуют `plc/PlcRegisters.kt` и ладдер-программе
`plc/DVP12SE11R_LineStop.md`.

| Регистр | Modbus-адрес | R/W | Назначение |
|---------|--------------|-----|------------|
| `D0` (`STATE`) | `0x1000` (4096) | R | Состояние сигнала: `1` = авария, `0` = линия работает |
| `D1` (`START_COUNTER`) | `0x1001` (4097) | R | Счётчик запусков (инкремент по спаду `X0`) |
| `D4` (`ACK_COUNTER`) | `0x1004` (4100) | R | Счётчик квитирований (инкремент по `D101 = 1`) |
| `D5` (`LAST_CAUSE`) | `0x1005` (4101) | R | Код последней подтверждённой причины |
| `D100` (`CAUSE_CODE`) | `0x1064` (4196) | W | Код причины от планшета |
| `D101` (`ACK_REQUEST`) | `0x1065` (4197) | W | Запрос квитирования: планшет пишет `1`, ПЛК сбрасывает `0` |

Приложение читает **только `D0..D5`** одним запросом из 6 регистров
(`PlcRegisters.d(STATE), 6`). Регистр `D200` есть только у эмулятора
(тест-хук), в реальной карте ПЛК его нет.

## Обмен (квитирование причины)

```
X0: 0 -> 1 (24 В, линия встала)   ПЛК: D0 = 1
                                  Android: создаёт аварию, время начала, статус «АВАРИЯ»

X0: 1 -> 0 (линию запустили)      ПЛК: D0 = 0, INC D1
                                  Android: фиксирует конец и длительность,
                                           показывает диалог выбора причины

Android: D100 = код, D101 = 1     ПЛК: D5 = D100, INC D4, D101 = 0, D100 = 0
                                  Android: видит рост D4, подтверждает случай
```

- Код причины (`D100`) формируется справочником: `пункт * 10 + причина`
  (см. [`CAUSE_CATALOG.md`](CAUSE_CATALOG.md)); максимум `129`. Комментарий
  «1..10, 99 = другая» в `PlcRegisters.kt` — устаревший.
- Случай в приложении закрывается **сразу** при выборе причины
  (`ackPending = true`), а квитирование отправляется в ПЛК фоном и повторяется
  (`ACK_RETRY_MS = 3000` мс, до `MAX_ACK_ATTEMPTS = 10` попыток), пока `D4` не
  вырастет.
- `D101` — импульсный флаг: после обработки ПЛК сам сбрасывает `D101` и `D100`.

## Длительность аварии

Приложение считает длительность **по своим часам**: от фронта `D0 0→1` до спада
`D0 1→0`, точность ~0.2 с (период опроса). Регистры `D6`/`D7` (сеть 6 ладдера,
необязательная) приложение **не читает**.

Следствие: если планшет перезапустился во время аварии, начало восстановить
нельзя — случай создаётся с текущего момента (см. правило `firstRead` в
[`ARCHITECTURE.md`](ARCHITECTURE.md)).

## Ладдер-программа ПЛК

Полное описание 5 обязательных сетей (сброс, авария, работа, счётчик запусков,
квитирование) и необязательной сети 6 (измерение `D6`/`D7`) — в
`plc/DVP12SE11R_LineStop.md`. Регистры доступны как holding registers с базовым
адресом `0x1000` «из коробки», отдельная настройка Modbus не требуется.
