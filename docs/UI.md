# Интерфейс приложения

Весь UI — Jetpack Compose (Material 3). Точка входа — `MainActivity` →
`MainScreen(vm)`. Ориентация — только **ландшафт** (`AndroidManifest.xml`).

## Главный экран (`ui/MainScreen.kt`)

### Верхняя панель

- Индикатор связи: `«Связь: <ip>:<port>»` (зелёный) или `«Нет связи»` (красный).
- Смена:
  - нет активной смены — кнопка **«Начать работу»** (диалог ввода фамилии);
  - есть смена — текст `«Оператор: Фамилия · с HH:mm:ss · длительность»` и
    кнопка **«Закончить работу»** (подтверждение).
- Кнопка **«Журнал»** — открывает журнал событий.
- Кнопка **«Настройки»** — сначала запрашивает код доступа.

### Карточка статуса (`StatusCard`)

Цвет и текст зависят от состояния:

| Условие | Текст | Цвет | Иконка |
|---------|-------|------|--------|
| нет связи | `НЕТ СВЯЗИ` | серый | — |
| `D0 = 1` | `АВАРИЯ` | пульсирующий красный | `!` |
| линия работает, есть незакрытые аварии | `ЛИНИЯ В РАБОТЕ` | жёлтый | `✔` |
| всё закрыто | `ЛИНИЯ В РАБОТЕ` | зелёный | `✔` |

При потере связи показывается текст ошибки (`snapshot.lastError`). При активной
аварии — «Сигнал аварии активен (линия остановлена)», при незакрытых случаях —
«Незакрытых аварий: N — укажите причину».

### Активные аварии

Список незакрытых случаев (`!closed`). Карточка показывает начало, при
завершении — конец и длительность (у идущей аварии длительность «тикает»),
статус «Причина отправлена, ожидаем подтверждения ПЛК…» при `ackPending` и
кнопку **«Указать причину»** (повторно открывает диалог).

### История

Закрытые случаи (`closed`), отсортированы по `stopTime` по убыванию. Строка:
причина (`causeLabel`) и `Начало / Конец / Длительность`.

## Диалоги

| Диалог | Файл | Назначение |
|--------|------|------------|
| `CauseDialog` | `ui/CauseDialog.kt` | Трёхшаговый выбор причины |
| `AccessDialog` | `ui/Dialogs.kt` | Ввод кода доступа к настройкам |
| `OperatorDialog` | `ui/Dialogs.kt` | Начать смену (фамилия) |
| `EndShiftDialog` | `ui/Dialogs.kt` | Подтверждение завершения смены (Да/Нет) |
| `LogsDialog` | `ui/Dialogs.kt` | Просмотр журнала (до 300 записей) |
| `SettingsDialog` | `ui/SettingsDialog.kt` | IP/порт ПЛК, очистка истории |

### `CauseDialog` — выбор причины

Показывается автоматически **только для последней** незакрытой аварии (по спаду
сигнала) либо по кнопке «Указать причину» в карточке. Шаги:

1. **Категория** — 4 кнопки из `CauseCatalog.categories`.
2. **Пункт** — кнопки пунктов выбранной категории.
3. **Причина** — кнопки причин; для «Другой причины» появляется поле ручного
   ввода (`canConfirm` требует непустой текст).

Кнопки: **«Назад»** (на шаг выше), **«Подтвердить»** (доступна на шагах 2–3),
**«Закончить работу»** (завершить смену, не выходя из аварии) и **«Позже»**
(`dismiss` — случай остаётся активным). В шапке диалога — начало, конец и
длительность аварии.

### Настройки

Перед открытием `AccessDialog` проверяет код через `AccessGuard.check()`
(SHA-256-хеш, сам код в приложении не хранится и не отображается).
`SettingsDialog` меняет IP и порт (`updateIp`/`updatePort` перезапускают опрос)
и очищает историю (`clearHistory` — аварии и журнал, смены сохраняются).

## Форматирование

`util/TimeFormat.kt`:
- `formatTime` — `dd.MM.yyyy HH:mm:ss`;
- `formatShortTime` — `HH:mm:ss`;
- `formatDuration` — `«N ч NN мин NN с»`, `«N мин NN с»` или `«N с»`; `null` и
  отрицательные → `«—»`.
