# Спецификация: выгрузка данных по авариям

Задача приоритета 1 (версия 0.2.0) из [`PLAN.md`](PLAN.md). Дать оператору
сформировать отчёт по авариям за нужный период и выгрузить его с планшета.

## Пользовательский сценарий

1. На главном экране — новая кнопка **«Отчёт»** (рядом с «Журнал»).
2. Открывается экран/диалог отчёта, где задаются фильтры (см. ниже).
3. Нажатие **«Сформировать»** показывает предпросмотр: количество записей и
   суммарную длительность.
4. Кнопка **«Выгрузить»** формирует CSV и открывает системное меню «Поделиться»
   (или сохраняет файл во внешнюю папку приложения).
5. Опционально: «Очистить фильтры» и «По умолчанию» (текущая смена / сегодня).

## Фильтры

| Фильтр | Поле БД | Поведение |
|--------|---------|-----------|
| **Тип аварии** | `alarms.cause_code` | Мультивыбор: категория → пункт → причина из `CauseCatalog`, либо «Все причины». Пустое значение = без фильтра. |
| **Кто был на смене** | `shifts.operator` (JOIN по `alarms.shift_id`) | Выпадающий список уникальных операторов (`ShiftDao.all()`), плюс «Без смены» (`shift_id IS NULL`) и «Все». |
| **Дата** | `alarms.stop_time` | Диапазон «с / по» (даты включительно), по локальному времени планшета. |
| **Время** | `alarms.stop_time` | Диапазон времени суток «с / по» (`HH:mm`), применяется к времени начала аварии; поддерживает интервал через полночь (например, `22:00–06:00`). |

Все фильтры комбинируются по логическому **И**. Пустой фильтр не ограничивает
выборку.

## Колонки отчёта

| Колонка | Источник |
|---------|----------|
| № | `alarms.id` |
| Оператор | `shifts.operator` |
| Начало (дата и время) | `alarms.stop_time` |
| Конец | `alarms.start_time` |
| Длительность | `alarms.duration_ms` (формат `formatDuration`) |
| Код причины | `alarms.cause_code` |
| Причина | `alarms.cause_path`, для «Другой» — `cause_text` |
| Статус | `closed` → «Закрыта» / «Активна» |
| Счётчик запусков | `alarms.start_counter` (`D1`, диагностика) |

Записи сортируются по `stop_time` по возрастанию.

## Реализация

### Запрос (новый метод `AlarmDao`)

Существующие `AlarmDao.all()` и фильтрация в Compose (`MainScreen`) для отчёта
не годятся — нужен SQL с соединением и условиями. Добавить:

```sql
SELECT a.*, s.operator AS operator_name
FROM alarms a
LEFT JOIN shifts s ON a.shift_id = s.id
WHERE a.stop_time >= :from AND a.stop_time <= :to
  AND (:allCauses OR a.cause_code IN (…))
  AND (:allOperators OR s.operator = :operator OR (:withoutShift AND a.shift_id IS NULL))
ORDER BY a.stop_time
```

Фильтр времени суток удобно применять в Kotlin по `stop_time % 86_400_000` либо
в SQL через `strftime('%H:%M', a.stop_time/1000, 'unixepoch', 'localtime')`.

Предикат фильтрации и построитель CSV должны быть **чистыми функциями** (без
`Context`), чтобы покрыть их unit-тестами без Android.

### Модель

Ввести `AlarmReportRow` (авария + `operatorName`) и `AlarmFilter`
(`from/to`, набор кодов, оператор, `withoutShift`, `timeFrom/timeTo`). Выборку
складывать в `AlarmDao.report(filter): List<AlarmReportRow>`.

### CSV

- Собственный генератор (сторонние библиотеки запрещены): разделитель `;`,
  кодировка **UTF-8 с BOM** (корректное открытие в Excel RU), заголовок на
  русском, экранирование `"` и `;` кавычками, переносы строк — `\r\n`.
- Имя файла: `linestop_alarms_YYYYMMDD_HHmm.csv`.

### Запись и передача файла

- Файл писать во внешнюю папку приложения
  (`context.getExternalFilesDir(null)/exports/`) — не требует разрешений.
- Поделиться через `FileProvider` (`androidx.core.content.FileProvider`):
  добавить `<provider>` в `AndroidManifest.xml` и `res/xml/file_paths.xml`,
  затем `Intent.ACTION_SEND` с `application/pdf`/`text/csv`. Дополнительно —
  кнопка «Сохранить в Загрузки» (MediaStore, API 29+).
- Импорт истории на планшет и синхронизацию не делаем — только выгрузка.

### UI

- Кнопка «Отчёт» в верхней панели `MainScreen`.
- Новый `ReportDialog` (Compose): фильтры, предпросмотр (N записей, суммарная
  длительность), кнопки «Сформировать», «Выгрузить», «Сбросить».
- После выгрузки — запись в журнал (`CAT_APP`: «Сформирован отчёт: N записей»).

## Изменения схемы БД

**Не требуются.** Все нужные поля уже есть в `alarms` и `shifts`.

## Тесты и проверка

- Unit-тесты предиката фильтра: дата, время, тип, оператор, «без смены»,
  интервал через полночь, пустые фильтры.
- Unit-тест генератора CSV: заголовки, экранирование, кодировка/BOM, пустой
  результат.
- Тесты `AlarmEngine` и Python-эмулятор не затрагиваются, но `py -3 -m unittest
  discover -s simulator -p "test_*.py" -v` должен оставаться зелёным.
- Ручная проверка: сформировать отчёт по тестовой выборке и открыть CSV в Excel.
