# Спецификация: web-выгрузка аварий

Задача приоритета 1 (версия 0.3.0) из [`PLAN.md`](PLAN.md).

**Важно:** выгрузка доступна только через **web-интерфейс** и только
**администратору**. Оператор на планшете выгрузкой не занимается и кнопки отчёта
у него нет.

> В проекте **сейчас web-версии нет** — есть только Android-приложение. Этот
> документ описывает, что нужно создать.

## Роли

| Роль | Где работает | Права |
|------|--------------|-------|
| Оператор | планшет (Android) | Ведёт смену, указывает причины. Без выгрузки. |
| Администратор | браузер (web-кабинет) | Смотрит и выгружает аварии с фильтрами. |

## Поток данных

1. Планшет ведёт локальную БД (`alarms`, `shifts`) как сейчас.
2. Планшет **синхронизирует** закрытые аварии и смены на сервер по локальной
   сети; при отсутствии связи копит очередь и повторяет отправку.
3. Администратор открывает web-кабинет, задаёт фильтры и выгружает CSV/Excel.

```
планшет ──(JSON/HTTPS, upsert)──► сервер (БД) ──(фильтры, экспорт)──► браузер админа
```

## Синхронизация (Android → сервер)

- Каждой установке приложения присваивается `device_id` (UUID), хранится в
  `SharedPreferences`.
- На планшете схема поднимается до **v3**: в `alarms` и `shifts` добавляются
  `device_id TEXT` и `synced INTEGER NOT NULL DEFAULT 0` (или отдельная таблица
  `sync_queue`).
- Фоновый воркер отправляет батч несинхронизированных записей и помечает их
  `synced = 1` после успешного ответа сервера.
- Серверная таблица: ключ `(device_id, local_id)`, upsert идемпотентен —
  повторная отправка не создаёт дубликат.
- Отправка не влияет на автомат аварий (`AlarmEngine`) и на офлайн-работу
  планшета.

## Web-кабинет

### Пользовательский сценарий

1. Администратор входит в web-кабинет (`логин / пароль`, роль admin).
2. На странице «Аварии» задаёт фильтры и нажимает **«Показать»**.
3. Видит таблицу и сводку (число записей, суммарное время простоя).
4. Нажимает **«Выгрузить CSV»** (или Excel) — браузер скачивает файл.

### Фильтры

| Фильтр | Поле | Поведение |
|--------|------|-----------|
| **Тип аварии** | `alarms.cause_code` | Мультивыбор: категория → пункт → причина из `CauseCatalog`, либо «Все причины». |
| **Кто был на смене** | `shifts.operator` (JOIN по `alarms.shift_id`) | Список операторов + «Без смены» (`shift_id IS NULL`) + «Все». |
| **Какая дата** | `alarms.stop_time` | Диапазон дат (с / по, включительно). |
| **Время** | `alarms.stop_time` | Диапазон времени суток `HH:mm`, в т.ч. через полночь (`22:00–06:00`). |

Фильтры комбинируются по **И**; пустой фильтр не ограничивает выборку.

### Колонки отчёта

| Колонка | Источник |
|---------|----------|
| № | `alarms.id` |
| Оператор | `shifts.operator` |
| Начало (дата и время) | `alarms.stop_time` |
| Конец | `alarms.start_time` |
| Длительность | `alarms.duration_ms` |
| Код причины | `alarms.cause_code` |
| Причина | `alarms.cause_path` (для «Другой» — `cause_text`) |
| Статус | `closed` → «Закрыта» / «Активна» |
| Счётчик запусков | `alarms.start_counter` (`D1`, диагностика) |

Сортировка по `stop_time` по возрастанию.

## API (предлагаемое)

| Метод | Назначение |
|-------|------------|
| `POST /api/v1/auth/login` | Вход администратора, сессия/JWT. |
| `POST /api/v1/sync` | Приём батча смен и аварий с планшета (upsert). |
| `GET /api/v1/alarms` | Выборка по фильтрам (JSON) для таблицы. |
| `GET /api/v1/alarms/export.csv` | CSV по тем же фильтрам. |

Параметры фильтра: `from`, `to`, `timeFrom`, `timeTo`, `causeCodes`,
`operator`, `withoutShift`.

## Экспорт

- **CSV**: разделитель `;`, кодировка UTF-8 с BOM (корректно открывается в
  Excel RU), заголовки на русском, экранирование `;` и `"`.
- **Excel (.xlsx)** — опционально; ограничение «без сторонних библиотек»
  относится только к Android-приложению, на сервере библиотека допустима.
- Имя файла: `linestop_alarms_YYYYMMDD_HHmm.csv`.

## Тесты и проверка

- Тесты серверной выборки: комбинации фильтров (дата, время, тип, оператор,
  «без смены», интервал через полночь, пустые).
- Тест идемпотентности `POST /sync` (повторная отправка не создаёт дубликат).
- Тест формата CSV (заголовки, экранирование, BOM).
- Android: тесты `AlarmEngine` и Python-эмулятор должны оставаться зелёными
  (`py -3 -m unittest discover -s simulator -p "test_*.py" -v`).

## Критерии готовности

- [ ] Данные с планшета доходят до сервера и сохраняются без дублей.
- [ ] Web-кабинет доступен администратору после авторизации.
- [ ] Фильтры «тип аварии», «кто был на смене», «дата», «время» работают и
      комбинируются.
- [ ] CSV скачивается из браузера и открывается в Excel без «кракозябр».
- [ ] `CHANGELOG.md` дополнен; при релизе подняты `versionCode`/`versionName`.

## Открытые вопросы

- Стек и хостинг сервера, наличие сервера на предприятии.
- Сетевая доступность планшета до сервера (подсеть/VPN).
- Нужна ли авторизация только для admin или ещё роли (технолог, руководитель).
