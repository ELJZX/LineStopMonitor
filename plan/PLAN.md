# План разработки Line Stop Monitor

Документ описывает направления развития приложения после версии **0.1.6**.
Основан на текущей кодовой базе; архитектура и модель данных — в
[`../docs/ARCHITECTURE.md`](../docs/ARCHITECTURE.md) и
[`../docs/DATA_MODEL.md`](../docs/DATA_MODEL.md).

## Текущее состояние

- Стабильно работают: опрос ПЛК по Modbus TCP (200 мс), уровневый автомат
  аварий (`AlarmEngine`), трёхшаговый выбор причины, смены операторов, журнал
  событий, локальная БД SQLite (schema v2), эмулятор ПЛК и тесты
  (51 unit + 8 интеграционных).
- Через UI доступны только просмотр истории и журнала. Отчётности и выгрузки
  данных нет.
- В `README.md` в разделе «Что нужно доработать» перечислены заготовки причин,
  выгрузка истории и авторизация оператора.

## Приоритет 1. Выгрузка данных по авариям

Ключевая задача — дать возможность сформировать и выгрузить отчёт по
зафиксированным авариям с устройства (файл + системный «Поделиться»/сохранение
в «Загрузки»).

**Фильтрация отчёта:**

- **тип аварии** — категория / пункт / конкретная причина из
  `CauseCatalog` (мультивыбор, «Все причины»); фильтр по `alarms.cause_code`
  или диапазону кодов;
- **кто был на смене** — оператор (`shifts.operator`), соединение
  `alarms.shift_id = shifts.id`; отдельный пункт «Без смены» для аварий с
  `shift_id IS NULL`;
- **какая дата** — диапазон дат (с / по) по началу аварии (`stop_time`);
- **время** — диапазон времени суток (с / по, `HH:mm`) в дополнение к датам,
  например для ночной смены.

Колонки отчёта: id, оператор, дата и время начала, конец, длительность, код
причины, путь причины (`Категория / Пункт / Причина`), свободный текст «Другой
причины», статус (`closed`), значение `D1`.

Подробная спецификация — в [`EXPORT_ALARMS.md`](EXPORT_ALARMS.md).

Ограничение: нельзя использовать сторонние библиотеки (Room, POI, CSV-парсеры),
поэтому выгрузка — собственный генератор CSV с разделителем `;` и UTF-8 BOM.

## Приоритет 2. Авторизация оператора

- Сейчас оператор вводит фамилию вручную (`OperatorDialog`) — опечатки и
  дубликаты в отчётах.
- Предлагается выбор из справочника операторов + необязательный PIN, с
  сохранением в таблице `operators` (миграция схемы до v3).

## Приоритет 3. Справочник причин

- Перенести причины в редактируемый источник (БД или импорт из файла), чтобы
  менять их без пересборки APK.
- Сохранить совместимость кодов (`пункт * 10 + причина`, `9` — «Другая»),
  так как коды пишутся в ПЛК (`D100`).

## Приоритет 4. Внешняя интеграция

- Отправка закрытых случаев на сервер/в 1С (REST/очередь), повтор при обрыве
  сети, идемпотентность по `alarm.id`.
- Возможна замена ручной выгрузки автоматической синхронизацией.
